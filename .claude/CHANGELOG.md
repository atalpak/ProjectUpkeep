## 2026-09-09 — Phase 3, agent team created

Owner approved the five-agent roster including `assessor` on 2026-09-09.

- **Created** `.claude/agents/` with five agents, each carrying its own brief
  rather than a one-line description:
  - `assessor` — opus, read-only. Independent evidence-led view of what to build
    next. Instructed to cite a file, query, test or measurement for every
    finding, and to say plainly when a question cannot be answered without real
    users rather than modelling a hypothetical one.
  - `architect` — opus, read-only. Impact maps before implementation. Carries
    this codebase's specific sensitivities: ownership/location decoupling, RLS as
    the single enforcement point, and the two open schema bets.
  - `implementer` — sonnet, read+write. The only agent with `Edit`/`Write`.
    Must run lint, typecheck and tests before calling anything done; must stop
    and hand back rather than redesign mid-build.
  - `reviewer` — sonnet, read-only. Ordered checklist, with the six specific
    constraint violations that are easy to introduce and silent in testing.
  - `triager` — haiku, read-only. Notices and hands off; explicitly told not to
    diagnose deeply, because that is what it exists to avoid paying for.
- **Created** `.claude/settings.json` (new, committed — distinct from the
  gitignored `settings.local.json`). Sets
  `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` and a `deny` list covering
  destructive database commands, force pushes, `rm -rf`, production deploys,
  reads of `.env` / `.env.local`, and writes to `archive/**` and `AGENTS.md`.
- **Amended** `ORGANIZATION.md` with two honesty notes: what "read-only" does
  and does not guarantee given that these agents hold `Bash`, and the unresolved
  tension between the reviewer gate and the pre-allowed `gh pr merge` in
  `settings.local.json`.

Model tiers follow the token-efficiency guidance: haiku for triage, sonnet for
implementation and review, opus only for the two read-only judgement roles.
**No global default `model` was set in `settings.json`** — that would override
the owner's own model choice in every session, which is not what the guidance
was asking for. Per-agent models carry it instead.

## 2026-09-09 — Phase 4, weekly self-review routine drafted

- **Created** `.claude/routines/weekly-self-review.md` — the prompt for a
  read-only weekly routine, kept in version control so it is reviewable and has
  a history. The owner schedules it himself at `claude.ai/code/routines`.
- **Amended** `ORGANIZATION.md` to point at it.

Three sections: whether the roster still fits the work that landed, whether the
experimental Anthropic features this setup depends on have moved, and whether a
full `assessor` run is due.

Two things written into the prompt on purpose:

- **It is told what it cannot see.** A cloud routine has the repository, not the
  session transcripts, so it cannot observe which agents were actually invoked.
  It must infer from git history and label inferences as such, rather than
  reporting usage it has no access to.
- **It is told a quiet week is a real result.** Without that, a recurring review
  manufactures proposals to justify its own existence, and stops being worth
  reading within a month.

It also carries the open question about whether `.claude/rules/*.md` `paths:`
frontmatter genuinely auto-loads — unconfirmed when built, and a useful finding
whenever it can be settled either way.
